# Phase G physical-phone pilot

**Status: awaiting approval, devices and reference equipment.** No participant trial, native share interaction, physical pulse measurement or motion measurement took place in this release review. The following is a local execution package for the existing [Stand Still](MOTION-VALIDATION.md) and [camera pulse](PULSE-B1.md) protocols. Running the commands creates worksheets or arithmetic summaries only.

## Before the phone sessions

1. Obtain the owner's written approval of this plan, the participant information and consent process, recruitment, data access and destruction date. Arrange appropriate scientific/privacy review. Testers can withdraw or skip without penalty. Use adults who can comfortably perform the existing tasks. Stop on discomfort. Never administer a substance, alter medication or deliberately destabilise a participant.
2. Prepare an exact-SHA HTTPS staging build, without paid AI and with room participation off. Record the health revision. Use one rear-camera iPhone in Safari and one Android phone in Chrome, both in the system browser. Record actual model, OS/browser version, floor, footwear, orientation and lighting in the device sheet; never send physical results to the public room. Record separate session conditions and actual trial order/time locally. Obtain permission before recording even coded measurements. Restrict access to the data folder and keep it outside Git, cloud sync and analytics. Do not enter names, dates of birth, device IDs, IP addresses, camera frames or raw motion traces in these sheets.
3. Run the following with Python 3 from the repository root. Substitute a new approved private folder. The generator refuses to overwrite an existing directory. The report can run on a blank file set and reports unrun slots. Retain every rejection, denial and incomplete slot.

   ~~~sh
   python3 docs/portfolio/phase-g-device-pilot.py create /private/local/kachka-pilot
   python3 docs/portfolio/phase-g-device-pilot.py report /private/local/kachka-pilot
   ~~~

4. Agree reference calibration and synchronization procedures, scoring gates and exclusions before testing. If no synchronized reference is available, record that explicitly. For motion percentage comparisons, predeclare what baseline magnitude is large enough for meaningful relative error in each source's units. If unknown, choose absolute-only differences. Document any protocol change before analysis.

## Operating the worksheets

**Motion.** Five coded participants × two phones × two days × three primary trials = 60 slots. Use one practice per phone before scored trials. Alternate first phone across participants, rest at least 30 seconds, fix foot position, chest position, floor and eye-level target. No deliberate motion during the primary set. Each primary slot records its first attempt; keep subsequent retries and practice in a separate local attempt log linked to the slot. Never replace a rejection with a successful retry.

Use `/lab/stand` on staging for the existing Stand component. After Use this reading, transcribe the summary metrics from the lab output. Also exercise the ordinary onboarding → baseline → check → ticket path on both platforms. A raw gyro unit is degrees per second and acceleration is metres per second squared. Enter the reported source (`gyroscope` or `acceleration`), protocol, placement, capture length, cadence, combined and lateral RMS, and any recovered/placement-changed flags. Use `unknown` for unobservable placement. For boolean observations enter `yes`, `no` or `unknown`. For a valid stable run the planned capture is 10 s including 2 s settling. Record individual interval median, p95 and worst gap if a supervised inspector can obtain them locally; otherwise mark unavailable in notes. Use the protocol statuses in the script; reserve `usable` for a valid uninterrupted first capture. Record the observed reason for an unusable recording.

Report availability across all attempts and among uninterrupted primary attempts per phone. Below 90% among uninterrupted trials triggers investigation. The script prints median/min/max per person/day/device/source/recovery, absolute differences for eligible first-to-later pairs, and first-of-day cross-day comparisons. Percentages require an eligible first baseline. Keep unverified placement, different sources, recovered versus unrecovered and incompatible protocols separate. Review lateral RMS and day-level summaries alongside the primary combined RMS. Count crosses of the provisional 30% product floor, examine variation and pause individual-change claims if crosses are frequent. No clinical pass threshold is established for the observed variability. A separate physical agreement experiment needs a rigidly aligned calibrated reference IMU, matched axes, synchronized markers before and after each recording, identical filter/window and paired signed/absolute errors over stationary and controlled movement. Availability, repeatability and reference agreement answer different questions.

**Pulse.** Three coded participants × two phones × ordinary/dim light × three independent primary captures = 36 slots. Seated rest for five minutes, hand supported, gentle same-finger contact over the chosen rear lens. Record actual torch state and changes in focus, exposure, frame cadence or gaps where observable. Use `/lab/pulse` and verify a subset through the ordinary optional-pulse flow including display and scoring provenance. Use synchronized single-lead ECG or a suitable validated ECG-based chest strap that exports timestamped RR intervals. Record alignment of the 15-second post-settling capture window in the local notes. Enter the mean **valid RR interval in ms** from that matched window; the report computes reference BPM as 60,000 divided by that mean. Record stillness separately from reference quality. Use `still=no` for confounding movement, and `reference_valid=no` for ECG artifact, loss of synchronization or absent reference. Mark unobservable conditions `unknown` and explain those decisions in notes. Do not pair a watch's recent display with the phone result or substitute missing intervals. Keep retries and combined attempts in a separate log, with both source windows identified; if either window cannot be matched, report recovery availability alone.

Primary statuses are measured, approximate, unreadable, unavailable, interrupted or skipped. Report each category and reference exclusions by phone and lighting. The provisional per-phone thresholds among still, reference-valid primary trials are ≥80% measured availability, median absolute error ≤5 bpm, and ≥90% of measured pairs within 10 bpm. The report also gives signed bias and largest absolute error. Small or incomplete aligned subsets, even when the numbers look favourable, require further testing. A resting pilot cannot establish accuracy across conditions, skin appearances, arrhythmias or exercise. Approximate and combined outcomes must never change a score; without physical evidence, keep pulse display-only for any limited beta or omit pulse from the release scope.

**Negative controls, lifecycle and native share.** The controls sheet schedules three repeats of each motion and pulse control on each phone. Log the actual outcome with a short non-identifying note. Keep functional probes separate from primary denominators.

Keep failures and missing observations explicit. Lower-level timing, comparative sensor agreement and clinical/test validity are separate sign-offs. The pilot tool prepares and summarizes evidence; a qualified reviewer must assess coverage, controls, uncertainty and retention before any broader claims.

## Stand timeout investigation

The broad flow runner historically waited exclusively for the success button **Use this reading**. One preserved diagnostic from Phase C shows the UI had already reached **Try that again** with “Too few continuous motion readings.” Run again and Skip were on screen. Its synthetic timer stream showed multiple dispatch gaps above 40 ms, with a maximum of 139.3 ms. At a typical median 16 ms interval the existing 2.5-period maximum is approximately 40 ms. Under that rule the delayed synthetic stream could not support an uninterrupted result. The older uninstrumented timeouts establish only that success was absent, not the reason in every run.

The Phase G motion browser check separately drops a 144 ms span from both sources using a controlled browser clock, confirms the retry and skip controls and zero capture listeners, then accepts a new continuous attempt. Its two wall-clock runs still depend on host scheduling. They now fail promptly with the actual refusal message, observed dispatch count and largest gap if quality falls short. A Playwright observation of HOLD is an approximation of the start boundary. These checks distinguish an expected data-quality rejection from a UI stuck in capture. Run them separately from CPU-intensive builds when characterizing timing. No phone cadence or physical acceptance rate follows from those results.
